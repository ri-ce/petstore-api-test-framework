# SauceDemo 网页自动化测试计划

## 1. 测试目标

验证 SauceDemo 公开演示商城的登录、商品浏览、排序、购物车和结算核心流程。
项目通过真实浏览器执行用户操作，并检查页面状态、提示信息和业务结果。

## 2. 被测系统

- 网站：`https://www.saucedemo.com/`
- 账号：`standard_user`
- 密码：`secret_sauce`
- 测试类型：网页端到端自动化测试
- 浏览器：Chromium

## 3. 测试范围

### 纳入范围

- 登录页面加载。
- 标准账号正常登录。
- 错误密码提示。
- 锁定账号被拒绝。
- 登录后退出。
- 商品列表数量。
- 商品价格和名称排序。
- 加入购物车和移除商品。
- 购物车商品展示。
- 结算表单必填校验。
- 完整下单流程。

### 不纳入范围

- 真实支付。
- 移动端兼容性。
- 大规模并发性能。
- 企业真实用户数据。

## 4. 页面对象设计

| 页面对象 | 职责 |
| --- | --- |
| LoginPage | 打开登录页、填写账号、执行登录 |
| InventoryPage | 商品列表、排序、购物车入口和退出 |
| CartPage | 查看购物车商品、进入结算 |
| CheckoutPage | 填写顾客信息、表单校验和完成订单 |

页面元素操作集中在 `ui_tests/pages/`。当网页结构改变时，优先调整页面对象，
测试用例仍保持稳定。

## 5. 测试数据

- 使用 SauceDemo 公开的标准测试账号。
- 顾客姓名和邮编仅用于演示结算，不代表真实个人信息。
- 每个测试使用独立的浏览器上下文，不共享登录状态和购物车。

## 6. 稳定性措施

- Playwright 默认等待元素出现或进入可操作状态，避免直接使用固定睡眠时间。
- 使用网站提供的 `data-test` 属性定位元素。
- 设置 15 秒元素等待和 30 秒页面导航超时。
- 测试失败时自动保存完整页面截图。
- 每个测试结束关闭浏览器上下文，隔离 Cookie 和页面状态。

## 7. 准出条件

- 12 条自动化用例全部通过。
- 登录、排序、购物车和结算主流程均有覆盖。
- 测试报告和失败截图目录可以查看。
- GitHub Actions 中网页测试执行成功。

## 8. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 网页元素属性变化 | 页面对象集中修改，不散落在测试中 |
| 页面加载速度波动 | 使用显式等待和合理超时 |
| 测试之间登录状态污染 | 每个测试创建独立浏览器上下文 |
| 公网短时不可用 | 报告保留失败信息，便于区分环境问题和业务缺陷 |
