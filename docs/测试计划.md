# CampusMart 接口测试计划

## 1. 测试目标

验证校园二手交易演示 API 的核心业务是否满足接口定义，重点检查登录鉴权、商品管理、
订单流程、库存一致性以及不同角色之间的权限边界。

## 2. 测试范围

### 纳入范围

- 登录、注销、Token 鉴权。
- 商品列表、分类、价格和关键词筛选。
- 商品新增、查询、修改和删除。
- 卖家、买家、管理员的权限控制。
- 下单、库存扣减、订单查询和取消。
- 取消订单后的库存恢复。
- 参数校验、错误码与响应结构。

### 不纳入范围

- 真实支付、物流和消息通知。
- 生产级安全、数据持久化和高可用。
- 大规模并发与容量测试。
- 前端页面和浏览器兼容性测试。

## 3. 测试策略

| 类型 | 方法 | 目的 |
| --- | --- | --- |
| 冒烟测试 | `pytest -m smoke` | 验证核心主流程可用 |
| 正向测试 | 合法数据调用接口 | 验证业务功能正确 |
| 负向测试 | 缺失参数、非法类型、越权访问 | 验证异常处理 |
| 边界测试 | 价格、库存、数量边界 | 验证边界条件 |
| 状态测试 | 下单、取消、重复取消 | 验证订单状态与库存一致性 |
| 权限测试 | 卖家、买家、管理员交叉操作 | 验证角色隔离 |

## 4. 测试环境

| 项目 | 配置 |
| --- | --- |
| 操作系统 | Windows 11，GitHub Actions Ubuntu |
| 语言 | Python 3.12+ |
| 测试框架 | Pytest 9.x |
| HTTP 客户端 | Requests 2.x |
| 被测服务 | Flask 3.x 本地演示 API |
| 报告 | Pytest HTML |

## 5. 数据控制

- 每个用例开始前调用测试专用重置接口恢复种子数据。
- 认证用户由 `seller`、`buyer`、`admin` fixtures 自动登录。
- 商品数据通过 fixture 创建，避免测试之间共享可变状态。
- 使用随机端口启动被测服务，避免端口冲突。

## 6. 准入与准出

准入条件：

- Python 依赖安装完成。
- 演示 API 健康检查返回 `200`。
- 测试数据文件可读取。

准出条件：

- 所有阻塞级问题已解决。
- 核心冒烟用例全部通过。
- 完整回归通过率达到预期，且无未处理失败。
- HTML 报告和 CI 结果可查看。

## 7. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 内存数据在服务重启后丢失 | 测试开始前自动重置种子数据 |
| 用例之间互相污染 | 每个用例前重置状态，动态创建业务数据 |
| 本地端口被占用 | 自动选择空闲端口 |
| CI 与本地环境不同 | GitHub Actions 使用 Python 3.12 执行完整回归 |
