# Swagger Petstore 接口测试计划

## 1. 测试目标

验证 Swagger Petstore v3 公开 REST API 的 OpenAPI 文档、宠物 CRUD、状态筛选、
库存查询和订单生命周期是否符合公开接口契约。

## 2. 被测系统

- 系统名称：Swagger Petstore v3
- API 地址：`https://petstore3.swagger.io/api/v3`
- 官方项目：`swagger-api/swagger-petstore`
- 接口规范：`https://petstore3.swagger.io/api/v3/openapi.json`

被测系统由 Swagger 官方维护，本项目只负责接口测试框架和测试设计。

## 3. 测试范围

### 纳入范围

- OpenAPI 文档可访问性和版本校验。
- 宠物与订单接口路径、HTTP 方法校验。
- 按状态查询宠物。
- 宠物创建、查询、修改和删除。
- 宠物不存在和 ID 类型错误。
- 库存状态映射查询。
- 订单创建、查询、删除和删除后查询。
- 订单不存在。

### 不纳入范围

- 用户管理接口。
- 宠物图片上传。
- 生产级性能、安全和稳定性。
- 企业真实业务数据。

## 4. 测试策略

| 类型 | 方法 | 目的 |
| --- | --- | --- |
| 冒烟测试 | `pytest -m smoke` | 验证核心公开接口可用 |
| 契约测试 | 解析 `/openapi.json` | 确认路径和 HTTP 方法存在 |
| 正向测试 | 创建并查询真实资源 | 验证业务字段和数据写入 |
| 状态测试 | 创建、更新、删除、再查询 | 验证资源生命周期 |
| 异常测试 | 不存在 ID、错误 ID 类型 | 验证 404 和 400 |
| 稳定性测试 | 超时、连接重试、唯一 ID、自动清理 | 降低公共环境影响 |

## 5. 测试数据

- `data/test_data.json` 保存宠物和订单的数据模板。
- 每个创建类用例生成随机唯一 ID，避免与公共环境中的其他数据冲突。
- `created_pet` 创建测试宠物，用例结束后自动删除。
- `created_order` 依赖测试宠物创建订单，结束后先删除订单再删除宠物。

## 6. 测试环境

| 项目 | 配置 |
| --- | --- |
| 操作系统 | Windows 11，GitHub Actions Ubuntu |
| Python | 3.12+ |
| 测试框架 | Pytest 9.x |
| HTTP 客户端 | Requests 2.x |
| 报告 | Pytest HTML |
| 外部依赖 | Swagger Petstore 公网 API |

## 7. 准入与准出

准入条件：

- 依赖安装完成。
- `/openapi.json` 可以访问。
- 宠物和订单目标接口存在。

准出条件：

- 核心冒烟用例全部通过。
- 完整回归通过率 100%。
- 测试资源清理完成。
- HTML 报告和 CI 结果可查看。

## 8. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 公共 API 被其他用户修改 | 使用随机唯一 ID，不依赖固定种子数据 |
| 公网短时超时或连接中断 | 配置超时和有限次数指数退避重试 |
| 公共环境残留测试数据 | 通过 fixture 在用例结束后自动删除 |
| 外部服务不可用 | 重试后明确失败，不使用假结果掩盖服务异常 |
